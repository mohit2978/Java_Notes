## Thread Creation in Java — In Depth

---

### Method 1: Extending the `Thread` Class

```java
class MyThread extends Thread {
    private String taskName;

    public MyThread(String taskName) {
        this.taskName = taskName;
    }

    @Override
    public void run() {
        for (int i = 1; i <= 5; i++) {
            System.out.println(taskName + " - Count: " + i);
            try {
                Thread.sleep(500); // pause for 500ms
            } catch (InterruptedException e) {
                System.out.println("Thread interrupted!");
            }
        }
    }
}

public class Main {
    public static void main(String[] args) {
        MyThread t1 = new MyThread("Thread-A");
        MyThread t2 = new MyThread("Thread-B");

        t1.start(); // ✅ starts a new thread
        t2.start(); // ✅ starts another new thread
    }
}
```

**Output (order varies every run):**
```
Thread-A - Count: 1
Thread-B - Count: 1
Thread-A - Count: 2
Thread-B - Count: 2
...
```

**What's happening here?**
- `MyThread` **inherits** from `Thread`
- You override `run()` — this is the code that runs in the new thread
- You call `start()` — this tells JVM to create a new thread and call `run()` internally
- Both threads run **simultaneously**, so output order is unpredictable

---

### ⚠️ Why NOT to call `run()` directly

```java
t1.run(); // ❌ WRONG — runs on main thread, no new thread created
t1.start(); // ✅ CORRECT — creates a new thread
```

Calling `run()` directly is just a normal method call — no new thread is created. Always use `start()`.

---

### The Big Problem with Method 1

Java supports **single inheritance only**. If your class already extends something, you're stuck:

```java
class MyThread extends Thread {   // ✅ works alone
}

class Animal {
    void eat() { }
}

class Dog extends Animal {        // already extending Animal
    // ❌ CANNOT also extend Thread — Java doesn't allow it
}
```

This is a fundamental limitation. If your class is part of an existing hierarchy, you **cannot** use this approach.

### Method 2: Implementing the `Runnable` Interface

```java
class MyTask implements Runnable {
    private String taskName;

    public MyTask(String taskName) {
        this.taskName = taskName;
    }

    @Override
    public void run() {
        for (int i = 1; i <= 5; i++) {
            System.out.println(taskName + " - Count: " + i);
            try {
                Thread.sleep(500);
            } catch (InterruptedException e) {
                System.out.println("Thread interrupted!");
            }
        }
    }
}

public class Main {
    public static void main(String[] args) {
        MyTask task1 = new MyTask("Task-A");
        MyTask task2 = new MyTask("Task-B");

        Thread t1 = new Thread(task1); // wrap Runnable in Thread
        Thread t2 = new Thread(task2);

        t1.start();
        t2.start();
    }
}
```

**Key difference:** `MyTask` is NOT a `Thread`. It's just a **task** (the logic). You wrap it inside a `Thread` object to run it.

This separation is very important — **the task and the thread are different things.**

---

### Now your Dog class can have threading too:

```java
class Dog extends Animal implements Runnable {  // ✅ perfectly fine
    public void run() {
        System.out.println("Dog thread running");
    }
}

Dog dog = new Dog();
new Thread(dog).start(); // ✅ works!
```

### Method 3: Lambda (Shorthand for Runnable)

Since `Runnable` has only **one method** (`run()`), it's a functional interface — so you can use a lambda:

```java
public class Main {
    public static void main(String[] args) {

        Runnable task = () -> {
            for (int i = 1; i <= 5; i++) {
                System.out.println("Lambda Thread - Count: " + i);
            }
        };

        Thread t = new Thread(task);
        t.start();

        // Or even shorter, inline:
        new Thread(() -> System.out.println("Inline lambda thread")).start();
    }
}
```

This is the same as implementing `Runnable` — just much cleaner syntax. No separate class needed.

## Why `Runnable` is Preferred — Clear Reasons

---

### Reason 1: Java has Single Inheritance

```java
// ❌ This breaks if your class already extends something
class MyService extends BaseService {
    // Cannot extend Thread here!
}

// ✅ This always works
class MyService extends BaseService implements Runnable {
    public void run() { /* your logic */ }
}
```

---

### Reason 2: Separation of Concerns

With `Thread` extension, you're mixing **what to do** and **how to run it** in one class.

With `Runnable`, they are cleanly separated:

```
Runnable  →  defines WHAT to do  (your logic)
Thread    →  defines HOW to run  (thread machinery)
```

```java
Runnable emailTask = () -> sendEmail();
Runnable reportTask = () -> generateReport();

// Same task, run differently:
new Thread(emailTask).start();                          // plain thread
executor.submit(emailTask);                             // thread pool
scheduledExecutor.schedule(emailTask, 5, TimeUnit.SECONDS); // delayed
```

The same `Runnable` can be reused across different execution strategies. A `Thread` subclass cannot.

---

### Reason 3: Works with Executors (Modern Java)

Modern Java rarely creates threads manually. Instead, it uses **thread pools** via `ExecutorService`. These only accept `Runnable` or `Callable` — not `Thread` subclasses:

```java
ExecutorService pool = Executors.newFixedThreadPool(4);

pool.submit(new MyTask());        // ✅ Runnable works
pool.submit(() -> doWork());      // ✅ lambda works

// pool.submit(new MyThread());   // ❌ awkward, Thread is not Runnable by design
```

---

### Reason 4: Better Object Design

Extending `Thread` means your class **IS-A** thread, which is conceptually wrong. A `BankTransaction` or `EmailSender` is not a thread — it's a task. Using `Runnable` means your class **HAS behavior that can be run** — much more accurate.

---

## Side-by-Side Comparison

| | `extends Thread` | `implements Runnable` |
|---|---|---|
| Inheritance | ❌ Blocks further inheritance | ✅ Class can still extend others |
| Reusability | ❌ Tightly coupled to Thread | ✅ Same task, multiple executors |
| Works with thread pools | ❌ Not cleanly | ✅ Yes, natively |
| Object design | ❌ Class IS-A thread (wrong) | ✅ Class HAS-A task (correct) |
| Code cleanliness | ❌ Verbose | ✅ Clean, especially with lambda |
| Preferred in Java | ❌ No | ✅ Yes |

---

## The Golden Rule

> **Always use `Runnable` (or lambda) to define your task. Let `Thread` or `ExecutorService` worry about how to run it.**

## Thread Methods — Complete Guide with Examples & Output

---

### 1. `sleep(long milliseconds)`

Pauses the **current thread** for a specified time. Other threads continue running.

```java
class SleepDemo extends Thread {
    private String name;

    public SleepDemo(String name) {
        this.name = name;
    }

    public void run() {
        for (int i = 1; i <= 3; i++) {
            System.out.println(name + " - Step " + i);
            try {
                Thread.sleep(1000); // pause this thread for 1 second
            } catch (InterruptedException e) {
                System.out.println(name + " was interrupted!");
            }
        }
    }
}

public class Main {
    public static void main(String[] args) {
        SleepDemo t1 = new SleepDemo("Thread-A");
        SleepDemo t2 = new SleepDemo("Thread-B");
        t1.start();
        t2.start();
    }
}
```

**Output:**
```
Thread-A - Step 1
Thread-B - Step 1
// (1 second pause)
Thread-A - Step 2
Thread-B - Step 2
// (1 second pause)
Thread-A - Step 3
Thread-B - Step 3
```

**Key Points:**
- `sleep()` is a **static** method — it always sleeps the **currently running** thread
- It does NOT release any lock it holds (important in synchronization)
- Must handle `InterruptedException`
- After sleep ends, thread goes back to **RUNNABLE** state (not immediately running)

### 2. `join()`

Makes the calling thread **wait** until the thread it's called on finishes.

```java
class Worker extends Thread {
    private String name;

    public Worker(String name) {
        this.name = name;
    }

    public void run() {
        for (int i = 1; i <= 3; i++) {
            System.out.println(name + " working... step " + i);
            try { Thread.sleep(500); } catch (InterruptedException e) {}
        }
        System.out.println(name + " DONE.");
    }
}

public class Main {
    public static void main(String[] args) throws InterruptedException {
        Worker w1 = new Worker("Worker-1");
        Worker w2 = new Worker("Worker-2");

        w1.start();
        w1.join(); // main thread WAITS here until w1 finishes

        System.out.println("Worker-1 finished. Now starting Worker-2.");

        w2.start();
        w2.join(); // main thread WAITS here until w2 finishes

        System.out.println("All workers done. Main thread continues.");
    }
}
```

**Output:**
```
Worker-1 working... step 1
Worker-1 working... step 2
Worker-1 working... step 3
Worker-1 DONE.
Worker-1 finished. Now starting Worker-2.
Worker-2 working... step 1
Worker-2 working... step 2
Worker-2 working... step 3
Worker-2 DONE.
All workers done. Main thread continues.
```

**Without `join()`**, output would be chaotic — main thread wouldn't wait for workers.

**Variants:**
```java
t1.join();          // wait forever
t1.join(2000);      // wait max 2 seconds, then continue anyway
t1.join(2000, 500); // wait max 2 seconds + 500 nanoseconds
```

### 3. `wait()` and `notify()`

These are used for **thread communication** — one thread waits for a condition, another thread signals it.

> ⚠️ `wait()` and `notify()` must ALWAYS be called inside a `synchronized` block.

**Real example — Producer & Consumer:**

```java
class SharedBox {
    private int item = -1;
    private boolean hasItem = false;

    // Producer calls this
    public synchronized void produce(int value) throws InterruptedException {
        while (hasItem) {
            System.out.println("Producer waiting... box is full");
            wait(); // releases lock and waits
        }
        item = value;
        hasItem = true;
        System.out.println("Produced: " + item);
        notify(); // wakes up the consumer
    }

    // Consumer calls this
    public synchronized void consume() throws InterruptedException {
        while (!hasItem) {
            System.out.println("Consumer waiting... box is empty");
            wait(); // releases lock and waits
        }
        System.out.println("Consumed: " + item);
        hasItem = false;
        notify(); // wakes up the producer
    }
}

class Producer extends Thread {
    private SharedBox box;

    public Producer(SharedBox box) { this.box = box; }

    public void run() {
        for (int i = 1; i <= 5; i++) {
            try {
                box.produce(i);
                Thread.sleep(500);
            } catch (InterruptedException e) {}
        }
    }
}

class Consumer extends Thread {
    private SharedBox box;

    public Consumer(SharedBox box) { this.box = box; }

    public void run() {
        for (int i = 1; i <= 5; i++) {
            try {
                box.consume();
                Thread.sleep(800);
            } catch (InterruptedException e) {}
        }
    }
}

public class Main {
    public static void main(String[] args) {
        SharedBox box = new SharedBox();
        new Producer(box).start();
        new Consumer(box).start();
    }
}
```

**Output:**
```
Produced: 1
Consumed: 1
Produced: 2
Consumed: 2
Produced: 3
Consumed: 3
Produced: 4
Consumed: 4
Produced: 5
Consumed: 5
```

**What happens step by step:**
```
1. Producer acquires lock → produces item → calls notify() → Consumer wakes up
2. Consumer acquires lock → consumes item → calls notify() → Producer wakes up
3. This ping-pong continues safely
```

**`wait()` vs `sleep()` — Critical Difference:**

| | `wait()` | `sleep()` |
|---|---|---|
| Releases lock? | ✅ YES | ❌ NO |
| Must be in synchronized block? | ✅ YES | ❌ NO |
| Who wakes it up? | Another thread calling `notify()` | Timer expires automatically |
| Belongs to | `Object` class | `Thread` class |

### 4. `notifyAll()`

Wakes up **ALL threads** waiting on the object's lock (not just one).

```java
class Scoreboard {
    private int score = 0;
    private boolean updated = false;

    public synchronized void updateScore(int newScore) throws InterruptedException {
        score = newScore;
        updated = true;
        System.out.println("Score updated to: " + score);
        notifyAll(); // wake up ALL waiting players
    }

    public synchronized void waitForScore(String playerName) throws InterruptedException {
        while (!updated) {
            System.out.println(playerName + " is waiting for score update...");
            wait();
        }
        System.out.println(playerName + " saw the score: " + score);
    }
}

public class Main {
    public static void main(String[] args) throws InterruptedException {
        Scoreboard board = new Scoreboard();

        // 3 players all waiting for score
        Runnable waitTask = () -> {
            try {
                board.waitForScore(Thread.currentThread().getName());
            } catch (InterruptedException e) {}
        };

        Thread p1 = new Thread(waitTask, "Player-1");
        Thread p2 = new Thread(waitTask, "Player-2");
        Thread p3 = new Thread(waitTask, "Player-3");

        p1.start(); p2.start(); p3.start();

        Thread.sleep(1000); // let all players start waiting

        // Now update the score — notifyAll wakes everyone
        board.updateScore(100);
    }
}
```

**Output:**
```
Player-1 is waiting for score update...
Player-2 is waiting for score update...
Player-3 is waiting for score update...
Score updated to: 100
Player-1 saw the score: 100
Player-3 saw the score: 100
Player-2 saw the score: 100
```

**`notify()` vs `notifyAll()`:**

| | `notify()` | `notifyAll()` |
|---|---|---|
| Wakes up | ONE random waiting thread | ALL waiting threads |
| Risk | Can cause starvation | Safer, all get a chance |
| Use when | Only one thread should respond | Multiple threads need to re-check condition |

### 5. `interrupt()`

Signals a thread to **stop what it's doing**. It sets an interrupted flag — the thread must check and handle it.

```java
class LongTask extends Thread {
    public void run() {
        System.out.println("Task started...");
        for (int i = 1; i <= 10; i++) {
            if (isInterrupted()) { // check if someone interrupted us
                System.out.println("Interrupt detected! Stopping at step " + i);
                return;
            }
            System.out.println("Working... step " + i);
            try {
                Thread.sleep(500);
            } catch (InterruptedException e) {
                // sleep() throws this when interrupted during sleep
                System.out.println("Interrupted during sleep! Stopping.");
                return;
            }
        }
        System.out.println("Task completed normally.");
    }
}

public class Main {
    public static void main(String[] args) throws InterruptedException {
        LongTask task = new LongTask();
        task.start();

        Thread.sleep(1800); // let it run for 1.8 seconds

        task.interrupt(); // send interrupt signal
        System.out.println("Interrupt signal sent!");
    }
}
```

**Output:**
```
Task started...
Working... step 1
Working... step 2
Working... step 3
Interrupt signal sent!
Interrupted during sleep! Stopping.
```

### 6. `yield()`

A **hint** to the scheduler that the current thread is willing to pause and let other threads run. Not guaranteed — scheduler may ignore it.

```java
class YieldDemo extends Thread {
    private String name;

    public YieldDemo(String name) {
        this.name = name;
    }

    public void run() {
        for (int i = 1; i <= 5; i++) {
            System.out.println(name + " - " + i);
            Thread.yield(); // hint: let someone else run
        }
    }
}

public class Main {
    public static void main(String[] args) {
        new YieldDemo("Thread-A").start();
        new YieldDemo("Thread-B").start();
    }
}
```

**Output (varies, but more interleaved than without yield):**
```
Thread-A - 1
Thread-B - 1
Thread-A - 2
Thread-B - 2
Thread-A - 3
Thread-B - 3
```

### 7. `isAlive()` and `getState()`

Check the current status of a thread:

```java
public class Main {
    public static void main(String[] args) throws InterruptedException {
        Thread t = new Thread(() -> {
            try { Thread.sleep(2000); }
            catch (InterruptedException e) {}
        });

        System.out.println("Before start: " + t.getState());  // NEW
        System.out.println("Is alive: " + t.isAlive());       // false

        t.start();
        System.out.println("After start: " + t.getState());   // RUNNABLE or TIMED_WAITING
        System.out.println("Is alive: " + t.isAlive());       // true

        t.join();
        System.out.println("After finish: " + t.getState());  // TERMINATED
        System.out.println("Is alive: " + t.isAlive());       // false
    }
}
```

**Output:**
```
Before start: NEW
Is alive: false
After start: TIMED_WAITING
Is alive: true
After finish: TERMINATED
Is alive: false
```

|---|---|---|---|

| `notify()` | `Object` | ❌ No | Wake ONE waiting thread |
| `notifyAll()` | `Object` | ❌ No | Wake ALL waiting threads |
| `interrupt()` | `Thread` | ❌ No | Signal thread to stop |
| `yield()` | `Thread` | ❌ No | Hint to let others run |
| `isAlive()` | `Thread` | — | Check if thread is still running |
| `getState()` | `Thread` | — | Get current thread state |
