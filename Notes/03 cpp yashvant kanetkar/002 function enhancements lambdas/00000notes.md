### 🧠 Why use constexpr?
- Performance: evaluated at compile time = no runtime overhead

- Correctness: ensures immutability and predictability

- Required: for things like array sizes, template arguments, etc.

```cpp

constexpr int square(int x) {
    return x * x;
}

int main() {
    constexpr int val = square(5); // evaluated at compile-time
    int arr[val]; // valid: size known at compile time
}

```

Everytine input is same so function runs at compile-time!! If we do square(k) where k is we taking from keyboard at run-time so for that function will run at runtime as input coming at runtime!!

⚠️ Rules (in C++11):
- Must return a single expression

- No try, goto, or dynamic memory

- Everything used inside must also be constexpr

C++14 and newer relax these rules, allowing multiple statements and if/switch inside constexpr.

## endl vs \n

|Use	|Preferred|
|-------|---------|
|Just new line (no flush needed)	|✅ \n
|New line + flush output buffer	|✅ std::endl

✅ \n – Just a newline character
```cpp
std::cout << "Hello\n";
```
- Only inserts a newline character.

- Does not flush the output buffer.

- ✅ Faster (especially in loops).

- Recommended when you don't need to flush immediately.

✅ std::endl – Newline + flush
```cpp

std::cout << "Hello" << std::endl;
```
- Inserts a newline and then flushes the output buffer.

Useful when:

- You want to force the output to appear immediately (e.g., debugging).

- You're writing to a file or console and need real-time output.

### 🔁 What is flushing?
- Normally, std::cout uses a buffer for performance.

- Flushing forces it to write contents immediately (to screen or file).

- Flushing often is slow (I/O is expensive), so avoid endl in tight loops.

🧪 Performance Example:
```cpp

for (int i = 0; i < 100000; ++i) {
    std::cout << i << '\n'; // Fast
    // std::cout << i << std::endl; // Much slower
}
```
Using std::endl here will flush every line, causing a major slowdown.

### 🧠 Rule of Thumb:
|If...	|Use|
|-------|---|
Writing to console in a loop	|\n
Writing to file in a loop	|\n + ofstream.flush() when needed
Need immediate output (debugging/logging)	|std::endl
At end of a short program	|Either is fine

 #### What does capture mean in lambda?
“Capture” means making external (local) variables available inside the lambda function body.

Captured variables come from the surrounding scope, and you can either:

- Copy them (by value), or

- Reference them (by reference).

✅ When to use lambda capture list:
Lambda captures are used when:

- You want the lambda to access variables from its surrounding scope without explicitly passing them as parameters.

- You want to store or defer execution of a lambda (e.g., callbacks, threads, event systems).

- You want a lambda to "remember" its environment at the time it was created — like a closure in other languages.

### 📘 Example 1: [] – Capture Nothing
```cpp

int x = 10;
auto f = []() {
    std::cout << "Hello\n";
};
f(); // ✅ OK
```
🟢 Output:

```text
Hello
```
❌ Explanation: x is not accessible because we didn’t capture it.
If you tried to use x inside the lambda, it would cause a compile-time error.

### 📘 Example 2: [=] – Capture All By Value (copy)
```cpp

int x = 10, y = 20;
auto f = [=]() {
    std::cout << "x = " << x << ", y = " << y << "\n";
};
f();
```
🟢 Output:

```text
x = 10, y = 20
```
🧠 Explanation:

The lambda copies x and y from the outer scope when it’s defined.

Cannot update inside lambda as both are read-only for lmabda

### 📘 Example 3: [&] – Capture All By Reference
```cpp

int x = 10;
auto f = [&]() {
    x += 5;
};
f();
std::cout << "x = " << x << "\n";
```
🟢 Output:
```text
x = 15
```

🧠 Explanation:

x is captured by reference, so modifications inside the lambda affect the original x outside.

### 📘 Example 4: [x] – Capture x By Value Only
```cpp

int x = 10;
auto f = [x]() {
    std::cout << "x inside lambda: " << x << "\n";
};
x = 20;
f();
```

🟢 Output:

```text
x inside lambda: 10
```

#### 🔍 Key Moment:
- At the moment you write [x], the lambda captures a snapshot copy of x, which is 10.

- The lambda now has its own private copy of x that will never change.

- Even though you later update x = 20, that only affects the original x, not the lambda's copy.

🧠 Explanation:

Captures x by value (copy).

The lambda keeps the old value (10), even if x is changed later.


### 📘 Example 5: [&x] – Capture x By Reference
```cpp

int x = 10;
auto f = [&x]() {
    x = x + 5;
};
f();
std::cout << "x = " << x << "\n";
```
🟢 Output:

```text
x = 15
```
🧠 Explanation:

x is captured by reference, so the lambda changes the original x.

### 📘 Example 6: [=, &y] – Mix: Everything by Value, y by Reference
```cpp

int x = 5, y = 7;
auto f = [=, &y]() {
    // x is copied; y is referenced
    // x++; // ❌ error: cannot modify copy without `mutable`
    y++;
    std::cout << "x = " << x << ", y = " << y << "\n";
};
f();
std::cout << "Outside y = " << y << "\n";
```
🟢 Output:

```text
x = 5, y = 8
Outside y = 8
```
🧠 Explanation:

x is copied (not modifiable unless you use mutable)

y is a reference — so it's updated both inside and outside.

### 📘 Example 7: mutable with [x] (value capture, modifiable)
```cpp

int x = 10;
auto f = [x]() mutable {
    x += 5;
    std::cout << "Inside lambda: x = " << x << "\n";
};
f();
std::cout << "Outside: x = " << x << "\n";

```
🟢 Output:

```text
Inside lambda: x = 15
Outside: x = 10
```

🧠 Explanation:

mutable allows modifying a copy inside the lambda unlike ex-2.

Original x outside remains unchanged.

### 📘 Example 8: Capture in Loop — [] vs [=] vs [&]
```cpp

for (int i = 0; i < 3; ++i) {
    auto f = [=]() {
        std::cout << "Value = " << i << "\n";
    };
    f();
}
```
🟢 Output:

```text
Value = 0
Value = 1
Value = 2
```
🧠 Explanation:

Each lambda captures a copy of i as it was during that loop iteration.

### Min heap as cpp by default is max heap

```cpp

#include <iostream>
#include <queue>
#include <vector>

using namespace std;

int main() {
    // Min-heap lambda comparator (smaller values have higher priority)
    auto cmp = [](int left, int right) {
        return left > right;
    };

    // Declare min-heap priority queue using the lambda comparator
    priority_queue<int, vector<int>, decltype(cmp)> minHeap(cmp);

    // Push elements
    minHeap.push(10);
    minHeap.push(5);
    minHeap.push(20);
    minHeap.push(1);

    // Pop and print
    while (!minHeap.empty()) {
        cout << minHeap.top() << " ";
        minHeap.pop();
    }

    return 0;
}

```

decltype(cmp) is a C++ keyword expression that deduces the type of the variable or expression cmp.

🔍 Example:
Let's say you have this lambda function:

```cpp

auto cmp = [](int a, int b) {
    return a < b;
};
```
Here, cmp is a lambda function, and its type is compiler-generated and anonymous — you can't name it directly.

Now, if you want to declare another variable or parameter with the same type as cmp, you can use decltype(cmp):

```cpp

decltype(cmp) cmp2 = cmp;  // cmp2 has the same type as cmp
```
In PQ ,decltype(cmp) is used to tell the compiler: “use the same type as the lambda cmp

output:

### Sort 

```cpp
#include <iostream>
#include <vector>
#include <algorithm>  // for sort

using namespace std;

int main() {
    vector<int> nums = {5, 2, 9, 1, 7};

    // Lambda for descending order
    sort(nums.begin(), nums.end(), [](int a, int b) {
        return a > b;  // bigger elements come first
    });

    // Print result
    for (int num : nums) {
        cout << num << " ";
    }

    return 0;
}
```
