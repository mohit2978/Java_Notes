## Method References

### What is a Method Reference?

A method reference is simply a **shorthand for a lambda** that does nothing but call an existing method.

```java
// Lambda
list.forEach(s -> System.out.println(s));

// Method Reference — exact same thing, cleaner
list.forEach(System.out::println);
```

The `::` operator is used to refer to a method without calling it.

---

### The 4 Types

---

### 1. Static Method Reference
**Syntax:** `ClassName::staticMethod`

```java
// Static method
public class MathUtils {
    public static int doubleIt(int n) {
        return n * 2;
    }
}

// Lambda version
List<Integer> nums = List.of(1, 2, 3, 4);
nums.stream()
    .map(n -> MathUtils.doubleIt(n))
    .forEach(System.out::println);

// Method reference version
nums.stream()
    .map(MathUtils::doubleIt)       // cleaner!
    .forEach(System.out::println);
```

---

### 2. Instance Method Reference (on a specific object)
**Syntax:** `instance::instanceMethod`

```java
String prefix = "Hello, ";

// Lambda
list.stream().map(s -> prefix.concat(s));

// Method reference — calling concat on the specific object 'prefix'
list.stream().map(prefix::concat);
```

```java
// Another common example
Printer printer = new Printer();  // has method print(String s)

// Lambda
list.forEach(s -> printer.print(s));

// Method reference
list.forEach(printer::print);
```


---

### Why No Argument in Method Reference?

When you write `prefix::concat`, you are **not calling the method** — you are just **pointing to it**.

Java will **automatically pass the argument** when the stream processes each element.

---

### What Actually Happens Step by Step

```java
String prefix = "Hello, ";
List<String> list = List.of("Alice", "Bob", "Charlie");

// Lambda — you EXPLICITLY pass s
list.stream().map(s -> prefix.concat(s));

// Method Reference — Java IMPLICITLY passes each element
list.stream().map(prefix::concat);
```

Both are **100% identical**. The method reference is just syntactic sugar.

---

### How Java Reads It Internally

```java
// When you write this:
list.stream().map(prefix::concat);

// Java internally expands it to:
list.stream().map(s -> prefix.concat(s));
//                  ↑
//         Java fills this in for you automatically
//         from the stream's element type
```

---

### The Key Insight

`map()` expects a **Function\<String, String\>** — meaning it knows:
- it will receive **one String input**
- it must **return one String output**

So when you give it `prefix::concat`, Java knows:

```
"I need to pass one String to this reference"
         ↓
prefix.concat( autoFilledByJava )
         ↓
prefix.concat("Alice")   → "Hello, Alice"
prefix.concat("Bob")     → "Hello, Bob"
prefix.concat("Charlie") → "Hello, Charlie"
```

---

### Think of It Like This

```java
// Method reference is like handing over a RECIPE, not cooking it
prefix::concat  
// ↑ "Here is the method to call — figure out the ingredients yourself"

// Lambda is like giving step-by-step instructions
s -> prefix.concat(s)
// ↑ "Take s, pass it to concat, return the result"
```

The **stream** is the one doing the calling — it takes each element and feeds it into whichever form you gave it.

---

### Prove They Are Identical

```java
Function<String, String> lambda = s -> prefix.concat(s);
Function<String, String> methodRef = prefix::concat;

System.out.println(lambda.apply("Alice"));     // Hello, Alice
System.out.println(methodRef.apply("Alice"));  // Hello, Alice
// Exact same output!
```

Both are just implementations of `Function<String, String>` — Java calls `.apply("Alice")` on both, and both forward to `prefix.concat("Alice")`.

---

### Summary

| | Lambda | Method Reference |
|---|---|---|
| You write | `s -> prefix.concat(s)` | `prefix::concat` |
| Argument `s` | Written explicitly | Supplied automatically by Java |
| Who calls the method | You describe how | Java figures it out from context |
| Result | Same | Same |

> **The argument is always there — you just don't write it in a method reference. Java infers it from the functional interface and passes it automatically.**

### 3. Instance Method Reference (on an arbitrary instance)
**Syntax:** `ClassName::instanceMethod`

This is the **trickiest one**. The first parameter becomes the object the method is called on.

```java
// Lambda
List<String> names = List.of("alice", "bob", "charlie");
names.stream()
    .map(s -> s.toUpperCase())   // s is the object, toUpperCase called on it
    .forEach(System.out::println);

// Method reference — Java figures out that each element IS the object
names.stream()
    .map(String::toUpperCase)
    .forEach(System.out::println);
```

```java
// Sorting example
List<String> names = List.of("Charlie", "Alice", "Bob");

// Lambda
names.sort((a, b) -> a.compareTo(b));

// Method reference — 'a' is the object, 'b' is the argument
names.sort(String::compareTo);
```

> Think of it as: **first parameter = the object**, rest = arguments

---

### 4. Constructor Reference
**Syntax:** `ClassName::new`

```java
// A simple class
public class Person {
    String name;
    Person(String name) { this.name = name; }
}

// Lambda
List<String> names = List.of("Alice", "Bob", "Charlie");
List<Person> people = names.stream()
    .map(name -> new Person(name))
    .collect(Collectors.toList());

// Constructor reference
List<Person> people = names.stream()
    .map(Person::new)               // calls new Person(name) for each
    .collect(Collectors.toList());
```

---

### All 4 Types — Side by Side

```java
List<String> names = List.of("Alice", "Bob", "Charlie");

// 1. Static method reference
names.stream().map(StringUtils::toUpperCase);
//             ClassName::staticMethod

// 2. Instance method on specific object
String separator = "-";
names.stream().map(separator::concat);
//             instance::method

// 3. Instance method on arbitrary instance
names.stream().map(String::toLowerCase);
//             ClassName::instanceMethod  (element IS the object)

// 4. Constructor reference
names.stream().map(Person::new);
//             ClassName::new
```

---

### How It Maps to Functional Interfaces

Method references are just lambdas, so they fit any **functional interface**:

```java
// Supplier<T>  →  T get()
Supplier<List<String>> s = ArrayList::new;        // constructor ref
List<String> list = s.get();

// Consumer<T>  →  void accept(T t)
Consumer<String> c = System.out::println;         // instance ref
c.accept("Hello");

// Function<T,R>  →  R apply(T t)
Function<String, Integer> f = String::length;     // arbitrary instance ref
f.apply("Hello");  // 5

// Predicate<T>  →  boolean test(T t)
Predicate<String> p = String::isEmpty;            // arbitrary instance ref
p.test("");  // true

// BiFunction<T,U,R>  →  R apply(T t, U u)
BiFunction<String,String,String> b = String::concat;
b.apply("Hello, ", "World");  // "Hello, World"
```

---

### Lambda vs Method Reference — When to Use Which

```java
// ✅ Use method reference — direct method call, no extra logic
names.stream().map(String::toUpperCase);
names.forEach(System.out::println);

// ✅ Use lambda — when you have extra logic
names.stream().map(s -> s.toUpperCase() + "!");
names.stream().filter(s -> s.length() > 3 && s.startsWith("A"));

// ✅ Use lambda — when you need multiple statements
names.forEach(s -> {
    String upper = s.toUpperCase();
    System.out.println(upper);
});
```

> **Rule of thumb:** If your lambda body is just `x -> someMethod(x)`, replace it with a method reference.

---

### Quick Reference Cheat Sheet

| Type | Syntax | Lambda Equivalent |
|---|---|---|
| Static | `ClassName::staticMethod` | `x -> ClassName.staticMethod(x)` |
| Specific instance | `obj::instanceMethod` | `x -> obj.instanceMethod(x)` |
| Arbitrary instance | `ClassName::instanceMethod` | `x -> x.instanceMethod()` |
| Constructor | `ClassName::new` | `x -> new ClassName(x)` |

Method references make your code **shorter, more readable, and intention-revealing** — they let the method name speak for itself instead of wrapping it in boilerplate lambda syntax.

## Method References with Multiple Parameters

---

### The Key Rule

Method references **don't explicitly list parameters** — Java infers them from the **functional interface's signature**.

```java
// Lambda with 2 params
BiFunction<String, String, String> f = (a, b) -> a.concat(b);

// Method reference — Java knows BiFunction takes 2 params
BiFunction<String, String, String> f = String::concat;
```

---

### How Parameters Are Mapped

---

#### Static Method — All params passed as arguments

```java
public class MathUtils {
    public static int add(int a, int b) { return a + b; }
    public static int multiply(int a, int b, int c) { return a * b * c; }
}

// 2 parameters
BiFunction<Integer, Integer, Integer> add = MathUtils::add;
System.out.println(add.apply(3, 4));   // 7

// 3 parameters — need a custom functional interface
@FunctionalInterface
interface TriFunction<A, B, C, R> {
    R apply(A a, B b, C c);
}

TriFunction<Integer, Integer, Integer, Integer> mul = MathUtils::multiply;
System.out.println(mul.apply(2, 3, 4));  // 24
```

> For static methods: **all parameters = arguments to the method**, in order.

---

#### Arbitrary Instance Method — First param = object, rest = arguments

This is the most important rule to understand:

```java
// String's replace(char old, char new) — 2 params on the method
// But functional interface needs 3 params total:
//   param1 = the String object itself
//   param2 = first argument (old char)
//   param3 = second argument (new char)

// Custom functional interface
@FunctionalInterface
interface TriFunction<A, B, C, R> {
    R apply(A a, B b, C c);
}

TriFunction<String, String, String, String> replace = String::replace;
//                  ↑ object    ↑ arg1      ↑ arg2
System.out.println(replace.apply("hello", "l", "r")); // "herro"
```

```
Method:     String.replace(oldVal, newVal)
Mapping:    param1=object  param2=oldVal  param3=newVal
Interface:  TriFunction<String, String, String, String>
```

---

### Visual Mapping Diagram

```
STATIC METHOD REFERENCE  →  ClassName::method
─────────────────────────────────────────────
Interface params:  (A,    B,    C)
                    ↓     ↓     ↓
Method params:    (a,    b,    c)


INSTANCE METHOD REFERENCE  →  ClassName::instanceMethod
─────────────────────────────────────────────────────────
Interface params:  (A,         B,    C)
                    ↓           ↓     ↓
                  object    arg1   arg2
                  (method called on A, with B and C)
```

---

### Comparator — Classic 2-Parameter Example

```java
List<String> names = List.of("Charlie", "Alice", "Bob");

// Comparator<T> → int compare(T o1, T o2)  — 2 params

// Lambda
names.sort((a, b) -> a.compareToIgnoreCase(b));

// Method reference
// param1 = object (a), param2 = argument (b)
names.sort(String::compareToIgnoreCase);

System.out.println(names); // [Alice, Bob, Charlie]
```

---

### BiFunction Examples

```java
// String.indexOf(String str) — 1 method param
// BiFunction provides 2 → first is object, second is argument

BiFunction<String, String, Integer> indexOf = String::indexOf;
System.out.println(indexOf.apply("hello world", "world")); // 6


// String.substring(int start, int end) — 2 method params
// TriFunction provides 3 → first is object, rest are arguments

TriFunction<String, Integer, Integer, String> sub = String::substring;
System.out.println(sub.apply("hello world", 0, 5)); // "hello"
```

---

### Constructor Reference with Multiple Params

```java
public class Person {
    String name;
    int age;

    Person(String name, int age) {
        this.name = name;
        this.age  = age;
    }
}

// BiFunction — 2 params go directly to constructor
BiFunction<String, Integer, Person> creator = Person::new;
Person p = creator.apply("Alice", 30);
System.out.println(p.name + " - " + p.age);  // Alice - 30
```

---

### Custom @FunctionalInterface for 3+ Params

Java only provides `Function`, `BiFunction` out of the box. For 3+ params, define your own:

```java
@FunctionalInterface
interface TriFunction<A, B, C, R> {
    R apply(A a, B b, C c);
}

@FunctionalInterface
interface QuadFunction<A, B, C, D, R> {
    R apply(A a, B b, C c, D d);
}

// Usage
public class StringUtils {
    public static String format(String template, String name, int age) {
        return template.replace("{name}", name)
                       .replace("{age}", String.valueOf(age));
    }
}

TriFunction<String, String, Integer, String> fmt = StringUtils::format;
System.out.println(fmt.apply("Hi {name}, age {age}", "Alice", 30));
// "Hi Alice, age 30"
```

---

### Summary Table

| Method Type | Interface Params | Mapping |
|---|---|---|
| Static `(a,b,c)` | 3 params | `p1→a, p2→b, p3→c` |
| Instance `obj.method(a,b)` | 3 params | `p1→obj, p2→a, p3→b` |
| Constructor `new(a,b)` | 2 params | `p1→a, p2→b` |

### The Golden Rule 🔑

> For **static** methods → all interface params are **arguments**
>
> For **instance** methods → first interface param is the **object**, rest are **arguments**

Java always infers this from the **functional interface's signature** — you never write the parameters explicitly in the method reference itself.
